# S05 acceptance — npm fresh install enables Codex to invoke both agents

Section outcome (U06/P09/P10/P13, D08): a plain npm install only stages the
package and its versioned payload; an explicit `init` makes the CLI usable on
a verified PATH, installs the service, binds the managed Codex plugin/MCP,
and claims the Codex home in the global registry.

## Implemented surface

- `package.json` (a bounded `postinstall` coordination hook; bin entries `external-subagent`,
  `external-subagent-mcp`) with a release `files` allowlist.
- `cli/install/`: `layout` (package/payload layout), `payload` (manifest,
  digest, mode, Mach-O arm64, triple version agreement), `path` (report-only
  PATH findings; absolute stable entries), `codex` (managed plugin/MCP
  binding over the verified official CLI), `service-macos` (the one
  LaunchAgent template + bootstrap/bootout with a documented test seam),
  `reconcile` (D08 homes registry single owner), `recovery` (snapshots,
  journal, rollback), `init` (explicit-init coordination). The S02-era
  `cli/installer.mjs` and `cli/service.mjs` were superseded by these owners.
- `cli/commands/`: `plugin`, `daemon`, `maintenance` (uninstall now releases
  D08 claims; data-layer operations remain in `cli/maintenance.mjs`).
- `scripts/release/`: payload build (+ deterministic manifest), tarball
  static checks, controlled-prefix install/init check.
- Docs: `docs/operations.md`, `docs/compatibility/codex.md`.

## Known boundaries and risks

- Unix socket paths are bounded by macOS `SUN_LEN`; the daemon reports a
  clear error (`path must be shorter than SUN_LEN`) for oversized fixture
  homes. Real product paths (`~/Library/Application Support/...`) are well
  within the limit; tests use short bases.
- `init` cannot roll back Codex-side cache writes already performed by the
  official CLI if a later step fails; the D08 claim only happens after a
  successful binding, and `uninstall` releases claims through the same
  official commands.
- The launchctl seam (`EXTERNAL_SUBAGENT_TEST_NO_LAUNCHCTL=1`) neutralizes
  service bootstrap in fixtures; real bootstrap is exercised only by an
  authorized real-home init.
- Update/reconcile-on-upgrade is shared by the S05/S06 install owner; the
  active-task drain and vA→vB hot-swap claims remain bound to their explicit
  S06 evidence.
